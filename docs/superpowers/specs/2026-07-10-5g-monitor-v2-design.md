# 5G用户级公共监控速率统计工具 V2.0.0 设计规格

## 1. 目标与范围

### 1.1 产品定位
重新从零设计并实现一个仅需用户提供 MMF 文件即可自动完成业务识别与速率统计的图形化工具，核心特征包括：
- 不依赖基准文件正式运行
- 自动判断测试场景与实际业务
- 输出每段业务的开始时间、结束时间、业务类型、平均速率与时长
- 提供清晰可解释的识别依据

### 1.2 本次实现范围（V2.0.0）
核心输出字段：
- 开始时间（毫秒精度）
- 结束时间（毫秒精度）
- 业务类型
- 平均速率（Mbps）
- 时长（毫秒）

暂停实现的扩展指标：
- 峰值速率、削峰速率、前10%峰值
- 达标采样点数、满分门限采样点数
- 成功率、覆盖率、RSRP/SINR等
- 对比报告、标注文件、在线更新、远程授权

保留为后续版本路线：
- 全部历史功能将在后续版本逐步补齐

### 1.3 校准标准
- 共同基准一致项的起止时间：100%对齐
- 平均速率偏差：不超过10%
- 不能复制基准时间戳或数值
- 不虚构 MMF 中实际不存在的业务

### 2.3 输入限制
- 正式运行不要求用户提供基准文件
- 基准文件仅用于开发阶段校准与规则反推

- 待确认

统一字段结构：
| 字段 | 类型 | 说明 |
|------|------|------|
| 轮次序号 | 整数 | 该运营商下的业务轮次编号 |
| 业务类型 | 文本 | FTP下载/FTP上传/商店小文件/商店大文件/微信小包/微信大包 |
| 开始时间 | 时间戳 | 业务开始时间点，毫秒精度 |

| 置信度 | 浮点 | 0-1，识别置信度评分 |

## 4. 业务识别规则

### 4.1 业务类型定义
六类标准业务：
- FTP下载：约10秒，下行，流量大小不固定，通常为测试文件下载
- FTP上传：约10秒，上行，流量大小不固定，通常为测试文件上传
- 商店小文件下载：约60MB，下行
- 商店大文件下载：约1100MB，下行
- 微信小包上传：约5MB，上行
- 微信大包上传：约200MB，上行

### 4.2 组结构与顺序规则
- FTP组：FTP下载与FTP上传顺序可互换，两项间隔约5秒，FTP组完成后到下一组约15秒
- 商店组：固定小文件在前、大文件在后，两项各自有独立最长300秒等待时间，小完成后立即开始大文件，无固定间隔
- 微信组：固定小包在前、大包在后
- 三组整体顺序可变：FTP→商店→微信 或 FTP→微信→商店 或其他组合

### 4.3 明确禁止的识别方式
- 不采用30秒、60秒、120秒、180秒等固定时长切分轮次
- 不直接读取或复制基准时间戳
- 不虚构不存在业务

### 4.4 正确识别策略
综合多维度行为模式匹配：
- 方向：上行或下行
- 流量大小：与业务规格的匹配度
- 持续时长：与业务典型时长的接近度
- 相对顺序：组内小包/大包顺序、组间顺序
- 组间间隔：FTP→下一组的间隔特征
- 组内间隔：商店两项无间隔、微信两项紧邻

## 5. 场景推断与置信度

### 5.1 场景类型
- 标准六业务轮：完整轮次包含六项业务
- FTP专项：仅有FTP上传与下载
- 其他专项或不完整测试：根据实际流量行为如实识别

### 5.2 场景推断流程
1. 扫描完整数据集
2. 检查是否存在商店级下载流量（60MB/1100MB特征）
3. 检查是否存在微信级上传流量（5MB/200MB特征）
4. 检查是否存在FTP时长模式（约10秒）
5. 综合判断属于哪种场景类型

### 5.3 置信度计算
权重分配：
- 流量匹配度：0.4
- 时长接近度：0.3
- 顺序一致性：0.2
- 组关系合理性：0.1

阈值：
- 置信度 ≥ 0.6：正式识别
- 置信度 < 0.6：标记待确认，不计入正式统计

### 5.4 待确认片段处理
- 保留时间段与候选类型
- 提供识别依据说明
- 不计入正式业务结果
- 单独展示并导出到待确认Sheet

## 6. 信息架构（三页向导）

### 6.1 第一页：导入与预检
核心控件：
- 文件选择区：单选或多选
- 文件列表：显示已选文件名、格式、大小
- 自动识别结果区：
  - 格式类型（mmf/xlsx/xlsb）
  - 运营商识别（联通/电信/未知）
  - 总时间范围
  - 数据概览（采样点数、是否有重叠）
- 预检状态：正常/警告/错误
- 下一步按钮：进入识别页

错误处理：
- 格式不支持：跳过并提示
- 运营商无法识别：标记未知，提示用户确认（本次不计入运营商sheet）
- 时间重叠：标注并继续

### 6.2 第二页：识别与跟踪
核心控件：
- 开始识别按钮
- 进度条：当前处理进度
- 实时识别日志：
  - 当前判断的片段
  - 场景类型推断结果
  - 置信度评分
- 可展开的单片段详情：
  - 识别依据：方向、流量、时长、顺序、间隔
  - 匹配的业务类型
  - 置信度
- 场景类型显示：六业务轮/FTP专项/其他
- 下一步按钮：进入结果页

### 6.3 第三页：结果与导出
核心控件：
- 业务结果表格：
  - 字段：轮次序号、业务类型、开始时间、结束时间、时长、平均速率、方向、置信度
  - 支持按运营商、业务类型、轮次筛选
  - 支持排序
- 待确认片段折叠区：
  - 展示低置信片段
  - 提供候选类型
- 导出按钮：
  - 选择保存路径
  - 生成Excel
- 识别依据查看：
  - 选中某行后可查看该片段识别依据详情
- 返回按钮：返回第一页重新导入

## 7. 核心模块架构

### 7.1 模块列表
| 模块 | 职责 |
|------|------|
| 输入层 | MMFReader、ExcelMMFAdapter、统一接口IDataProvider |
| 运营商识别模块 | 从文件名、数据列、时间戳前缀推断运营商 |
| 场景推断模块 | 扫描整体数据，判断场景类型 |
| 业务识别引擎 | 综合方向、流量、时长、顺序、间隔判断业务类型 |
| 置信度计算模块 | 多维度评分，输出0-1置信度 |
| 待确认管理模块 | 低置信片段单独管理，提供候选类型 |
| 结果生成模块 | 将识别结果转为统一输出结构 |
| GUI层 | 三页向导界面，Tkinter或PyQt |
| 导出模块 | 生成Excel工作簿，按运营商分sheet |

### 7.2 模块关系图
输入层 → 运营商识别 → 数据合并与时间排序 → 场景推断 → 业务识别与置信评分 → 结果生成 → GUI展示 → 导出

---

## 8. 数据流

### 8.1 主数据流
1. 用户选择文件
2. 输入层识别格式并转换到内部DataFrame
3. 运营商识别模块标注每条记录的运营商
4. 多文件时按时间轴合并排序
5. 场景推断模块判断整体场景类型
6. 业务识别引擎逐片段分析
7. 置信度计算模块评分
8. 结果生成模块结构化输出
9. GUI展示结果
10. 用户导出Excel

### 8.2 校准数据流（开发阶段）
1. 加载两套基准文件
2. 逐字段共同核验，提取一致项作为校准基准
3. 与工具识别结果逐项比较
4. 差异项分析并调整识别规则
5. 循环直至达标

## 9. 错误处理

### 9.1 输入阶段错误
| 错误类型 | 处理方式 |
|----------|----------|
| 文件格式不支持 | 弹窗提示，跳过该文件，继续处理其他文件 |
| 文件损坏无法读取 | 弹窗提示，跳过该文件 |
| 运营商无法识别 | 标记未知，提示用户确认，该数据计入汇总sheet |
| 时间重叠 | 自动按时间顺序拼接，重叠部分标注并单独列出警告 |

### 9.2 识别阶段错误
| 错误类型 | 处理方式 |
|----------|----------|
| 无有效数据 | 提示并生成空结构，不虚构业务 |
| 置信度普遍过低 | 提示可能数据不符合已知场景，导出待确认片段 |
| 场景类型未知 | 标记为其他，如实识别实际存在的片段 |

### 9.3 导出阶段错误
| 错误类型 | 处理方式 |
|----------|----------|
| 保存路径不可写 | 提示并让用户重新选择路径 |
| Excel生成失败 | 提示详细错误信息，保留GUI结果 |
