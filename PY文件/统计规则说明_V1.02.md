## 一、方案核心：呼叫详情配准

**双输入**：
1. **UCM 监控文件**：mmf…(英文 bps) / 两江…(中文 Mbps)，**自动识别**
2. **业务日志**：参考文件的「呼叫详情」sheet（含每次业务的发起/完成时间、结果、时长、单次速率）

**为何不用纯 UCM**：mmf 的 117 列全是无线指标、**无业务标识**；FTP 下载流量(~1125MB)与应用商店大包(1100-1600MB)重叠，纯速率无法区分；FTP 每次 10 秒≠config `calc_seconds=30`。实测纯 UCM 去重后 153 点全判「未知业务」。

**配准方式**：用呼叫详情里每次业务的「发起/完成时间」去 UCM 截取对应时段，业务定位精确。

## 二、各字段数据源与算法

速率列=RLC，削峰 下行1000/上行200。达标门限 下行100/上行20。

### FTP下载 / FTP上传（采样点级 + 呼叫详情混合）
| 字段 | 数据源 | 算法 |
|---|---|---|
| 测试次数 | 呼叫详情 | FTPDownload/Upload 行数 |
| 采样点数 | UCM截取 | 各次时段内 UCM 点总和 |
| 下行/上行RLC平均吞吐率(均值) | **呼叫详情** | 各次「下载/上传平均速率」的均值 |
| 削峰后平均吞吐率 | UCM截取 | 截取点 `min(速率,1000/200)` 的均值 |
| 峰值吞吐率 | UCM截取 | 截取原始点 max |
| ≥100/>20 占比(达标) | UCM截取 | 截取削峰后点 ≥门限 的占比 |
| ≥1000/>200 占比(满分门限) | UCM截取 | 截取削峰后点 ≥削峰阈值 的占比 |
| 前10%峰值速率 | UCM截取 | 截取削峰后点降序，前 max(1,int(N×0.1)) 个的均值 |
| 成功率 | 呼叫详情 | 成功次数/总有结果次数 |

### 应用商店_小包/大包、微信_小文件/大文件
| 字段 | 数据源 | 算法 |
|---|---|---|
| 测试次数 | 呼叫详情 | 各自开始/完成时间有效行数 |
| 采样点数 | UCM截取 | 各次时段内 UCM 点总和 |
| 平均吞吐率 | **呼叫详情** | 各次「单次速率」的均值 |
| 单次平均时长 | 呼叫详情 | 各次 (完成-开始) 秒 的均值 |
| 中位值平均时长(大包/大文件) | 呼叫详情 | 各次时长 **中位数**（经参考核对为简单中位，非归一化） |
| 下载/上传成功率 | 呼叫详情 | 业务整体：成功/总有结果 |

## 七、操作步骤

1. 双击 `启动工具.command` 打开 V1.02。
2. 「UCM监控」选 mmf/两江 xlsx；「业务日志」选参考文件(含呼叫详情)。
3. 确认参数（RLC、削峰1000/200）。
4. 点「开始统计」→ 右侧宽表展示 42 列结果。
5. 点「导出Excel」→ 输出「统计结果(宽表)/UCM数据」。
6. 与参考文件「按文件」sheet 逐字段比对验证。
