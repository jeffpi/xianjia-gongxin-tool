## 四、判定规则

### 核心规则（二分类：小包 vs 大包）

由于泰尔网测（FTP下载）已有独立规则（见《规则分析FTP下载.md》），此处重点是**区分应用宝小包下载和大包下载**。

#### 规则 1：流量阈值（主规则，准确率 92%）

```
if dlRlc(Mbps) < 800:
    → 应用宝小包下载
else:
    → 应用宝大包下载
```

**联通验证**：准确率 289/314 = **92.0%**（仅大小包二分类）

**错误来源**：小包中有 16/202（7.9%）>=800MB，大包中有 9/112（8.0%）<800MB

#### 规则 2：流量 + 上行占比（增强规则，准确率 ~95%）

```
if dlRlc(Mbps) < 200:
    → 应用宝小包下载
elif dlRlc(Mbps) >= 1300:
    → 应用宝大包下载
elif dlRlc(Mbps) >= 800 and dlRlc(Mbps) < 1300:
    if 上行占比 >= 2%:
        → 应用宝小包下载  # 异常高流量但高上行占比→可能是小包中高流量段
    else:
        → 应用宝大包下载
elif dlRlc(Mbps) >= 200 and dlRlc(Mbps) < 800:
    if 上行占比 >= 1.5%:
        → 应用宝小包下载  # 中流量+高上行占比=小包
    elif MAC DL(Mbps) >= 500:
        → 应用宝大包下载  # 中流量+高MAC=大包起步段
    else:
        → 应用宝小包下载  # 保守判为小包（小包在200~500MB区占多数）
```

**上行占比** = `Uplink MAC Throughput(bps) / (Downlink MAC Throughput(bps) + Uplink MAC Throughput(bps) + 1) * 100`

#### 规则 3：联合三分类（与泰尔网测一起区分）

```
if dlRlc(Mbps) < 200 and 上行占比 >= 1.5%:
    → 应用宝小包下载
elif dlRlc(Mbps) < 200 and 上行占比 < 1.5%:
    → 泰尔网测下载 (起步段) / 应用宝小包下载 (模糊)
elif 200 <= dlRlc(Mbps) < 800:
    if 上行占比 >= 2%:
        → 应用宝小包下载
    elif MAC DL(Mbps) >= 500:
        → 应用宝大包下载 (起步段)
    else:
        → 泰尔网测下载 (主力区间)
elif 800 <= dlRlc(Mbps) < 1300:
    if 上行占比 >= 2%:
        → 应用宝小包下载 (异常高流量段)
    else:
        → 应用宝大包下载 (主力区间)
elif dlRlc(Mbps) >= 1300:
    → 应用宝大包下载
```

### 特征速查表

| 特征 | 应用宝小包下载 | 应用宝大包下载 | 泰尔网测下载 |
|------|:---:|:---:|:---:|
| dlRlc 中位 | **103~158 MB** | **1,132~1,137 MB** | 526~599 MB |
| dlRlc 典型范围 | 10~350 MB | 800~1,600 MB | 300~900 MB |
| MAC DL 中位 | **97~119 Mbps** | **651~667 Mbps** | 316~377 Mbps |
| 上行占比中位 | **2.4~2.6%** | 0.95~1.0% | 0.58~0.8% |
| ulRlc 中位 | 1.3~1.6 MB | 1.7~2.0 MB | 1.4~1.5 MB |
| DL MCS 中位 | 12~13 | 18~19 | 15~17 |
| RLC DL Delay 中位 | **1.7~3.3 ms** | **85~115 ms** | 26~53 ms |
| DL RB/Slot 中位 | 192~208 | 251~257 | 230~236 |
| 每会话分段数 | ~202 | ~112 | ~126 |

### 最终推荐规则（工程实现）

```python
def classify_appstore(row):
    """区分应用宝小包下载 vs 应用宝大包下载，假定已排除泰尔网测"""
    dl = row['dlRlc(Mbps)']
    mac_dl = row['Downlink MAC Throughput(bps)'] / 1e6
    mac_ul = row['Uplink MAC Throughput(bps)'] / 1e6
    ul_ratio = mac_ul / (mac_dl + mac_ul + 1) * 100

    # 高置信度：流量极端值
    if dl < 200:
        return '应用宝小包下载'
    if dl >= 1300:
        return '应用宝大包下载'

    # 中流量区：用上行占比辅助
    if dl >= 800:
        # 800~1300MB 区间
        if ul_ratio >= 2.0:
            return '应用宝小包下载'  # 小包高流量异常段
        return '应用宝大包下载'

    # 200~800MB 区间
    if ul_ratio >= 2.0:
        return '应用宝小包下载'  # 高上行占比=应用商店特征
    if mac_dl >= 500:
        return '应用宝大包下载'  # 高MAC=大包起步段
    return '应用宝小包下载'  # 保守判断
```

### 规则验证

| 验证项 | 联通 | 电信 |
|--------|------|------|
| 大小包二分类准确率（规则1） | 92.0% | — |
| 小包识别准确率 | ~88% | ~81% |
| 大包识别准确率 | ~81% | ~79% |

**注意**：以上准确率是基于**逐行单条记录**的判定。在实际工具中，业务识别是按**整个会话（businessId）**进行，聚合后的特征区分度更高。例如一个小包会话有 202 条记录，其中 68% 的记录 dlRlc<200MB，整个会话的流量中位 ~113MB，远小于大包会话的 1,132MB。

## 五、与 FTP 下载（泰尔网测下载）的区分

### 已有 FTP 下载判定规则（来自《规则分析FTP下载.md》）

```python
def is_ftp_download(row):
    # 方向：纯下行（dlRlc >> ulRlc）
    if row['dlRlc(Mbps)'] <= row['ulRlc(Mbps)'] * 10:
        return False
    # 速率：不能太低
    if row['dlRlc(Mbps)'] < 50:
        return False
    return True
```

### 应用商店小包 vs FTP 下载 核心差异

| 差异点 | 应用宝小包下载 | FTP下载（泰尔网测） |
|--------|:---:|:---:|
| **上行占比** | **2.4~2.6%** (明显更高) | 0.6~0.8% (极低) |
| dlRlc 流量 | 10~350 MB (小包) | 300~900 MB |
| MAC DL 速率 | <120 Mbps | 300~600 Mbps |
| RLC DL Delay | 1.7~3.3 ms | 26~53 ms |

**增强版联合判定（二分类：小包 vs FTP下载）：**

```python
def classify_small_vs_ftp(row):
    dl = row['dlRlc(Mbps)']
    ul_ratio = 上行占比

    if ul_ratio >= 1.5:
        return '应用宝小包下载'  # 高上行占比=应用商店特征
    if dl >= 400 and ul_ratio < 1.0:
        return '泰尔网测下载'    # 中高流量+极低上行=FTP下载
    if dl < 200:
        return '应用宝小包下载'  # 低流量=小包
    return '泰尔网测下载'       # 模糊判为FTP
```

### 应用商店大包 vs FTP 下载 核心差异

| 差异点 | 应用宝大包下载 | FTP下载（泰尔网测） |
|--------|:---:|:---:|
| dlRlc 流量 | **800~1,600 MB** | 300~900 MB |
| MAC DL 速率 | **650~670 Mbps** | 316~377 Mbps |
| RLC DL Delay | **85~115 ms** (极高) | 26~53 ms |
| 上行占比 | 0.95~1.0% | 0.6~0.8% |

**区分规则**：`dlRlc >= 800MB` 且 `MAC DL >= 500Mbps` 即可判定为大包。

## 六、异常样本分析

### 大包中流量 <200MB 的样本（6条联通/5条电信）

这些是大包下载的**起始段**（下载刚建立，流量还在爬坡）：
- 联通：第1秒 dlRlc=43MB, MAC DL=61Mbps（典型起始段）
- 时间集中在大包下载刚开始的时刻（22:54/23:00/01:26/01:58）
- 上行占比正常（~1%），与同会话其他大流量段一致

### 小包中流量 >=500MB 的样本（16条联通/19条电信）

这些是小包下载中的**高流量异常段**：
- dlRlc 范围：517~885 MB（联通）、516~940 MB（电信）
- 上行占比：中位 2.2~2.4%（**仍保持高上行占比特征**）
- 上行 MAC 中位 6.0~7.0 Mbps（**显著高于小包正常值 2.4~2.7 Mbps**）
- 这些段可能对应网络条件极好的场景或下载了大文件的应用

## 七、结论

1. **流量是核心区分因子**：`dlRlc < 200MB` 基本可判定为小包，`dlRlc >= 800MB` 基本可判定为大包，**准确率 92%**
2. **上行占比是强力辅助特征**：小包上行占比 2.4~2.6%，FTP下载仅 0.6~0.8%，**可用上行占比 >=1.5% 来区分**
3. **MAC DL 速率可用于细化**：小包 <120Mbps，大包 >650Mbps，FTP在 300~600Mbps 中间区
4. **RLC DL Delay 是确认大包的最强特征**：大包时延 >85ms，是小包（~2ms）的 40 倍以上
5. **规则对联通和电信均有效**，两者特征高度一致，可通用
