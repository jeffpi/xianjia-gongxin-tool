### 2.5 与前序/后序业务的关系

联通数据中，FTP下载段前后紧邻业务：
- 前序：应用宝小包下载（3个mmf）/ 微信小包上传（1个mmf）/ 无业务（多数）

电信数据中类似：
- 前序：nan（无业务）、应用宝小包下载、微信小包上传
- 后序：微信大包上传（最常见）、应用宝大包下载

**结论：FTP下载通常在测试轮转中处于"应用宝小包下载→FTP下载→微信大包上传"的序列中，但并非固定模式。**

## 四、判定规则断言

```
业务: 泰尔网测下载 (FTP下载)
条件: 方向=下行 AND 段流量 0.1~1.2 GB
辅助条件: 段长 2~19秒（典型8~18秒）, 段均速 150~900 Mbps, 
          单秒速率 50~1200 Mbps, 
          每段内上行始终 < 5 Mbps（仅有TCP ACK）
与前序关系: 通常前序为应用宝小包下载或nan，后序为微信大包上传，但非强制
```

### 确定性规则（硬条件）

符合以下**全部**条件即可判定为FTP下载：

1. **方向：纯下行**
   - dlRlc(Mbps) > ulRlc(Mbps) × 10
   - ulRlc(Mbps) < 5 Mbps（始终为TCP ACK级别）

2. **段流量：0.5~0.8 GB（MAC口径）**
   - 单段总下行流量在 300~800 MB

3. **段时长：8~19秒连续**
   - 每1秒1行，时隙连续无间隔

4. **速率：中高速**
   - 段内平均 dlRlc > 300 Mbps（典型 400~800 Mbps）
   - 单秒 dlRlc 最高可达 1200 Mbps

### 经验规则（辅助判断）

- 段内速率呈"爬坡→峰值→缓降"模式（第一秒最低，4~5秒后达峰值，最后1~2秒下降）
- 数据在 ALL_FTP_DETAIL 中按业务类型分组连续排列（id连续）
- 通常是同一mmf中**唯一**的纯下行大流量段，或有且仅有一条FTP下载段

## 六、建议实施方案

在UCM业务识别程序中，对未标记的ALL_FTP_DETAIL行，按以下顺序判断FTP下载：

```python
def is_ftp_download(row):
    # 核心：方向条件
    if row['dlRlc(Mbps)'] <= row['ulRlc(Mbps)'] * 10:
        return False  # 不是纯下行
    
    # 速率条件
    if row['dlRlc(Mbps)'] < 50:
        return False  # 速率太低
    
    return True  # 标记为FTP下载候选
```

建议结合**连续段**（连续5秒以上）来最终判断，避免将单条高dlRlc噪声点误判为FTP下载。
