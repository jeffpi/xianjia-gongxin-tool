# 5G用户级公共监控速率统计工具 — 统计规则说明 V1.01

> 用途：本文档逐条说明「统计结果」sheet 中每一个指标的定义、计算公式、数据来源（精确到列）、参数取值、计算示例与依据，供与需求方确认口径。所有「待确认」项集中在第八节。
> 版本：V1.01 ｜ 规则版本：2025-2026 年工信部测评用例 ｜ 编写日期：2026-06-23

---

## 一、版本与适用范围

- 工具基于 **2025-2026 年工信部测评用例**（路测方式由泰尔网测还原回 FTP 测试）。
- 本期覆盖 **数据背包（40%）** 的速率、应用商店下载、微信上传三类业务的统计计算；语音/OTT 背包不在本期范围。
- 统计结果对标原工具《5G用户级公共监控速率统计工具（2023年工信部测试）V6.xlsb》的字段体系，并按 2025-2026 新规则补充「成功率」等指标。
- 输出采用**扩充窄表**：每行一个细分业务，共 6 个固定业务行 + 13 个指标列。

---

## 二、输入文件格式

- 来源：UCM「用户级公共监控」导出的 `.xlsx`。
- 结构：前 7 行为元数据（标题/保存时间/用户名/总计条数等），**第 8 行为列表头**（程序按 `header=7` 读取）。
- 采样粒度：**1 秒级打点**（依据《测试过程监控方法》D 文档）。
- 必需字段（节选，共 107 列）：
  - `采集时间`（格式 `YYYY-MM-DD HH:MM:SS (xxx)`）
  - `载波聚合属性`（用于过滤：保留「非CA用户」「CA用户主小区」）
  - `QCI`
  - `下行MAC吞吐率(Mbps)` / `上行MAC吞吐率(Mbps)`
  - `下行RLC吞吐率(Mbps)` / `上行RLC吞吐率(Mbps)` ← **本期速率取此列**
- ⚠️ 输入文件**没有**「业务名称」「成功/失败」标记列，业务类型与成功率均需由速率行为间接推断（见第五、六节）。

## 三、全局参数（默认值，界面可改）

| 参数 | 默认值 | 说明 |
|---|---|---|
| QCI | 0（全部） | 0=不过滤；>0 时仅保留该 QCI |
| 速率取值列 | **RLC** | 速率指标取 RLC 吞吐率（对标 V6；MAC 含重传偏高，仅作参考） |
| 下行削峰速率 | **1000 Mbps** | 每点 `min(原始, 1000)` |
| 上行削峰速率 | **200 Mbps** | 每点 `min(原始, 200)` |
| 下行达标门限 | 100 Mbps | 达标速率占比的门限 |
| 上行达标门限 | 20 Mbps | 达标速率占比的门限 |
| 场景类型 | 场景 | 场景/道路（满分门限参考：场景 900/道路 800） |

> 削峰阈值 1000/200 为本期默认（config 可改）；V6 原工具为 900/180。差异见第八节待确认 2。

---

## 四、数据预处理流程

1. **解析输入**：跳过前 7 行元数据，第 8 行起为数据；解析 `采集时间` 为时间类型（`采集时间_解析`）。
2. **清洗**：`"-"` 视为空并前向填充；`bps` 单位的 RLC 列换算为 Mbps（本数据集 RLC 列已为 Mbps，不触发）。
3. **过滤**：时间窗（可选）→ QCI（0=不过滤）→ 载波聚合属性（保留非CA用户、CA用户主小区）。
4. **方向识别**：按所选速率列（RLC）计算上下行比值，比值>10 且超过该方向最小速率阈值则判定为该方向的有效点；**同一秒同方向仅保留速率最大的一个采样点**（去重）。
5. **业务分段**：同方向且相邻时间差 ≤8 秒的连续点归为一段；段内一旦方向改变或间隔>8 秒则截断开新段。
6. **削峰**：对每个采样点 `削峰后 = min(原始速率, 削峰阈值)`，产出 `削峰后下行RLC` / `削峰后上行RLC` 两列。
7. **统计**：见第五节（速率类，采样点级）+ 第六节（成功率/时长类，段级）。

---

## 五、速率类指标（FTP下载 / FTP上传）

> 数据来源：`削峰后下行RLC吞吐率(Mbps)`（下行业务）/ `削峰后上行RLC吞吐率(Mbps)`（上行业务）。统一使用**削峰后**序列（对标 V6「削峰后平均吞吐率」）。

| 指标 | 定义与公式 | 依据 |
|---|---|---|
| **均值速率** | 该业务所有采样点「削峰后速率」的算术平均：`mean(削峰后速率)` | V6「削峰后平均吞吐率」 |
| **前10%峰值速率** | 削峰后速率降序排列，取前 `max(1, int(N×0.1))` 个采样点（N=采样点数）的**算术平均** | 文档「削峰后自高向低取 TOP10% 采样点的速率」；「平均」口径见待确认 4 |
| **达标速率占比** | 削峰后速率 ≥ 达标门限（下行 100 / 上行 20 Mbps）的采样点数 ÷ 总采样点数 ×100% | 文档明确门限 100/20 |
| **满分门限占比（附加）** | 削峰后速率 ≥ 削峰阈值（下行 1000 / 上行 200 Mbps）的采样点占比。对标 V6 的「≥900M/≥180M 占比」 | V6 宽表对应字段 |

**计算示例（两江测试文件，RLC 列）**：
- FTP下载：41 次 / 1292 点 → 均值速率 **867.45 Mbps**、前10%峰值速率 **1000.0 Mbps**（最高 10% 点均被削峰至 1000）、达标占比 **97.52%**、满分门限占比 **66.18%**。
- FTP上传：26 次 / 808 点 → 均值速率 **180.02 Mbps**、前10%峰值速率 **200.0 Mbps**、达标占比 **99.38%**、满分门限占比 **69.06%**。

> 说明：前 10% 峰值若等于削峰阈值，说明该业务最高 10% 的采样点原始速率均超过削峰上限，被统一 clamp 到上限——这是削峰后的正常表现。

## 六、成功率与时长类指标（应用商店 / 微信）

### 6.1 业务段时长（基础量，修复了 V1.00 的 bug）
- **定义**：一个业务段内，最后一个采样时间与第一个采样时间之差（单位：秒）。
- 公式：`段时长 = (段内 max(采集时间) − min(采集时间)).total_seconds()`
- ⚠️ V1.00 误将「采样点个数」当作时长，V1.01 已修正为真实秒数。

### 6.2 大包/大文件 中位数时长；小包/小文件 平均时长
- **小包 / 小文件 平均时长** = 该业务所有「完整段」时长的**算术平均**。
- **大包 / 大文件 中位数时长** = 该业务所有「完整段」时长的**中位数**。
- 「完整段」= 段累计流量落在该业务的完整流量区间（见 6.3）。仅完整段参与时长统计（不完整段未下载完成，时长无意义）。
- 依据：V6 对大文件业务输出「单次平均时长」+「中位值平均时长」，小文件输出「单次平均时长」。本期按需求：大包取中位数、小包取平均（不做流量归一化，见待确认 5）。

### 6.3 流量完整性（用于成功率与完整段判定）
- 段累计流量（MB）= 段内「有效速率(Mbps)」之和 ÷ 8（Mbps·s → MB）。
- 各业务的完整流量区间（= config 的 flow_min ~ flow_max）：

| 业务 | 完整区间 (MB) |
|---|---|
| 应用商店_小包（泰尔网测） | 60 ~ 140 |
| 应用商店_大包（我的世界） | 1100 ~ 1600 |
| 微信_小文件（5M） | 2.5 ~ 8 |
| 微信_大文件（200M） | 160 ~ 240 |

### 6.4 下载成功率 / 上传成功率（业务整体，流量完整性代理判定）
- **口径**：成功率 = 完整段数 ÷ 该业务（大+小包合并）识别段总数 ×100%。
  - 识别段总数 = 被归为该业务的全部段（含完整段 + 大包下载不完整段）。
  - 「大包下载不完整段」= 流量落在「小包上限 ~ 大包下限」间隙（应用商店 140~1100 MB；微信 8~160 MB）的段，归为该业务大包的失败尝试。
- **局限（见待确认 1）**：小包失败段（流量 < 小包 flow_min，如 <60 MB）因与背景小流量噪声难以区分，**不计入**分母，故成功率主要反映大包完整性 + 小包完整段；纯 UCM 数据无法得到真实前台成功率。
- **计算示例（两江测试文件）**：应用商店整体下载成功率 **40.0%**（小包 1 段完整 + 大包 4 段中部分完整）；该文件无微信上传业务。

## 八、评分权重参考（本期不做评分折算，仅列示）

数据背包 40%，道路 0.7 / 场景 0.3。数据背包内（据测评用例 slide2）：
- 下行：达标占比 5% + 均值 3% + 前10%峰值 2% = 10%
- 上行：达标占比 5% + 均值 3% + 前10%峰值 2% = 10%
- 应用商店：成功率 2% + 小包时长 5% + 大包时长 3% = 10%
- 微信：成功率 2% + 小文件时长 5% + 大文件时长 3% = 10%

评分法：成功率类=百分比等比折百分制；时长/质量类=同组排序取前 X% 作满分门限。**本期仅输出统计值，不折分。**

## 九、待与需求方确认的假设清单

1. **成功率**：本期为「流量完整性代理判定」，非真实前台成功率；小包失败段不识别（局限）。是否需要前台测试日志配合做真实成功率？
2. **削峰阈值**：本期默认下行 1000 / 上行 200 Mbps；V6 原工具为 900 / 180。以哪个为准？
3. **大/小包流量区间**：取 config/V6 工具 sheet 口径（60-140/1100-1600、2.5-8/160-240 MB）；测评用例文档另有单点值（60/1100、5/200 MB）。以区间还是单点为准？
4. **前 10% 峰值速率**：取「TOP10% 采样点的平均值」（文档原文「自高向低取 TOP10%」未含「平均」二字）。确认为平均值？
5. **大包时长算法**：本期为「各段实际时长的简单中位数」；V6 字段名「中位值平均时长」+「中位流量」疑似按 `中位流量` 归一化。是否需要改为归一化口径？
6. **速率列**：取 RLC（对标 V6，更真实但 UCM 可能缺失）；是否统一 RLC，缺失时回退 MAC？
7. **均值/达标/TOP10% 统一用削峰后 RLC 列**（V1.00 均值用未削峰列）。确认统一为削峰后？
8. **满分门限占比（附加列）**：是否需要保留该列（对标 V6 的 ≥900/≥180 占比）？
